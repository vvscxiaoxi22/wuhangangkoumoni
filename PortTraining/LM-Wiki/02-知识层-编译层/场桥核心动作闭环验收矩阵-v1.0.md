## 2. 闭环判定规则

一个动作只有同时满足以下条件，才能标记为“操作闭环已实现”：

1. **入口存在**：键盘、操控台或`equipment.action`能够发起动作。
2. **前置条件受控**：设备状态、安全条件和互斥条件在执行前检查。
3. **执行唯一**：同一动作不会被重复执行；正式接口按`operationRunId + actionId`幂等。
4. **成功可确认**：有明确状态变化和成功回执，不依赖目测。
5. **失败可确认**：拒绝、超时或安全禁止有原因码，且原状态不被破坏。
6. **反馈可观察**：位置、速度、锁销、着箱、连接状态和安全状态可被读取。
7. **结果可留证**：日志包含版本、输入、关键数值、结果和关联标识。
8. **可恢复**：拒绝后可修正重试；故障后进入安全状态；重启不会伪造成功。

当前场景执行链以v16为状态机基线，后续已加入v17 Standalone输入、大车/鸣笛/夹轮器、低空防碰/HUD、控制电源/急停/显式故障复位、大车/小车锚定、吊具泵/尺寸及旋转逻辑。v24曾在旧8回路/16绳腿拓扑上取得Harness、Unity程序集编译、+3°模型旋转/松手停止/自动回零以及随后30吨完整链证据；这些只能证明历史实现，不证明v30直绳拓扑。当前v30代码和程序集编译通过，但全套Unity Play必须重跑。整个场景仍未接入统一`PortTraining.Contracts`的Named Pipe传输、跨进程持久去重、结果持久化和重启恢复，因此不能称为港口实训平台正式工单闭环。

## 4. 通用验收前置条件

- 场景只有一个`YC_RuntimeRoot`和一个`YardCraneEightRopeMaxPrototypeRig`。
- 启动日志中的`model`与`profile`必须与本文档一致。
- 必须依次出现`YC_EIGHT_ROPE_MAX_READY`和`YC_EIGHT_ROPE_MAX_PRETENSIONED`；READY摘要应为`ropes=8, visualRopes=8`。
- Play拓扑门禁必须出现`YC_EIGHT_STRAIGHT_ROPE_TOPOLOGY_PASS visualRopes=8, legacyDeadEndLegs=0`；若存在`DeadEndLeg`或可视绳体数量不等于8，立即失败。
- 自动空载回归必须出现`YC_EIGHT_ROPE_MAX_PASS`，不得出现`YC_EIGHT_ROPE_MAX_FAIL`。
- 8根独立直绳及其上、下附件必须绑定完成，状态不得出现NaN或Infinity；真实模型自带的静态绳网格与Obi运行绳不得同时显示。
- 30吨测试箱使用`containerGrossMassKg=30000`；允许范围为`2200～40500kg`。
- 每个手动用例开始前只允许在空载、静止且非预张紧/载荷交接阶段按`R`安全复位；不满足条件必须输出拒绝日志且状态保持不变。
- 验收日志必须保留完整时间顺序，不能只截取单条PASS。

### YC-ACT-09 重载下降和落箱

| 项目 | 验收要求 |
| --- | --- |
| 前置条件 | 箱体锁定，小车位于目标箱位上方且水平速度接近0 |
| 操作 | 按`S`下降，在箱体回到落箱参考高度后松键 |
| 成功状态 | 水平误差≤`0.20m`、垂向误差≤`0.15m`、偏航误差≤`3°`、组合体速度≤`0.05m/s`，并连续保持`0.25s` |
| 安全联锁 | 下降中不得自动解锁；未静止时解锁必须拒绝 |
| 失败状态 | 穿透地面、触地弹跳持续、落箱未确认却允许解锁 |
| 必须证据 | `YC_CONTAINER_LANDED`记录水平、垂直、偏航、速度和稳定保持时间 |
| 当前结论 | 历史旧拓扑曾以水平`0.023m`、垂直`0.035m`、偏航`0.02°`、速度`0.034m/s`和稳定`0.26s`取得落箱确认；v30直绳拓扑尚未重跑，且仍无真实着箱/载荷传感 |

### YC-ACT-10 悬空或运动中拒绝解锁

| 项目 | 验收要求 |

| 前置条件 | 箱体已锁定，且未落稳或组合体速度大于`0.05m/s` |
| 操作 | 按`L`请求解锁 |

### YC-ACT-16 吊具左右回旋与自动回零

| 项目 | 验收要求 |
| --- | --- |
| 前置条件 | 八绳MAX就绪、吊具泵开启、非自动演示；`SpreaderPhysicalRotationBound=true` |
| 操作 | 分别维持左/右旋转到±3°后松开；在任一非零角度请求回零；回零途中再给手动方向输入验证打断 |
| 成功状态 | 逻辑角度与物理角度误差≤`0.02°`；吊具模型、灰盒、碰撞体、传感器、四锁销挂点及已锁箱体同步旋转；松手即停；回零平滑收敛到`≤0.01°`；手动输入立即取消自动回零 |
| 安全边界 | 吊具泵关闭时方向输入不改变角度、回零请求被拒绝；八绳滑轮、上架刚体根和绳长约束不得被主动回旋驱动 |
| 失败状态 | 只有HUD数值变化而模型不动、逻辑/物理角度分离、箱体不跟随、碰撞/传感几何未同步、回零超时、绳索异常或30吨组合抖动超出既有门槛 |
| 必须证据 | `YC_SPREADER_ROTATION_PHYSICAL_BOUND`、`YC_SPREADER_ROTATION_STARTED/STOPPED`、`YC_SPREADER_ROTATION_RETURNED_TO_ZERO`及`YC_SPREADER_ROTATION_PLAY_SMOKE_PASS`；带载时还必须取得30吨完整链PASS |
| 当前结论 | `部分实现`：旧拓扑v24曾通过+3°逻辑/物理同步、松手停止、自动回零和30吨完整链；v30直绳拓扑尚未重跑旋转/回零及带载Play，负向限位、回零中手动打断、泵关闭拒绝和带载旋转也仍待专项验收 |

## 7. 推荐执行顺序

### 7.1 正常全流程

1. 启动场景，取得`READY → PRETENSIONED → PASS`。
2. 空载执行一次A/D启动和停车，再执行一次W/S起升和停车。
3. 执行YC-ACT-16吊具左右旋转、松手停止、自动回零和手动打断；确认模型与逻辑角度一致。
4. 在未对准状态请求锁箱，确认`LOCK_REJECTED`且状态不变。
5. 下降对箱并锁箱，确认`LOCKED → LOAD_TRANSFER_READY locked=True`。
6. 带箱执行小角度旋转并回零，确认箱体、碰撞和传感节点同步且八绳物理门槛不被破坏。
7. 在净空不足时请求横移，确认小车不动。
8. 起升到安全净空，确认`COLLIDER_RESTORED`，松键并等待`SETTLED`。
9. 左右各完成一次横移和停车，确认存在可控惯性且指标不超限。
10. 回到目标箱位，下降至落箱高度。
11. 在尚未落稳时请求解锁，确认`UNLOCK_REJECTED`。
12. 落稳后解锁，确认`UNLOCKED → LOAD_TRANSFER_READY locked=False`。
13. 空吊具再次起升，确认箱体不再跟随且质量恢复空载。
14. 结束用例后执行调试复位，等待重新预张紧。

### 7.2 任一用例立即失败条件

- 未出现`YC_EIGHT_STRAIGHT_ROPE_TOPOLOGY_PASS`，或出现`legacyDeadEndLegs>0`、可视绳体数量不等于8。
- 出现`YC_EIGHT_ROPE_MAX_FAIL`、`YC_LOADED_HOIST_SETTLE_TIMEOUT`、NaN、Infinity或未处理异常。
- 锁箱/解锁拒绝后状态发生改变。
- 低净空时小车仍移动，或悬空/运动中成功解锁。
- 绳索锚点不随小车、上架或卷筒运动。
- 吊具—箱体组合出现持续上下抖动、穿透、弹飞或非预期瞬移。
- 为通过用例而放宽`8mm`、`0.35m`、`1.5°`、锁箱或落箱门槛。
