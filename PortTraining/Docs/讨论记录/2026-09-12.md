- 根因：`StudentEntry`历史上同时承担登录和内嵌教师首页，登录成功只切同一壳层页面；场景构建维护器与旧验证器也仍固定在四场景/同场教师页假设。
- 实际修改：
  - 新增`YardCraneTeacherSideShell`与独立一次性`YardCraneTeacherHomeHandoff`；教师登录改为真实加载`TeacherHome`，无新鲜教师身份直接打开该场景会清理残留并退回入口。
  - `TeacherHome`的两个根UIDocument分别绑定`Resources/TeacherSide/Display1UI/TeacherSideShell.uxml`和`Resources/TeacherSide/Display2UI/TeacherSideLower.uxml`及各自PanelSettings；目标Display为0/1，参考分辨率均为1920×1080。场景不含StudentEntry/StudentSide壳层或其UXML/Panel GUID。
  - `StudentEntry`删除内嵌教师首页，只保留学生/教师登录；教师退出加载全新的入口，教师与学生交接、FallbackSession、TrainingIdentity均显式清理，避免跨角色残留。
  - Build Settings与`YardCraneBuildAutomation`、`ProjectScaffolder`、`YardCraneOperationalSceneBuilder`统一为五场景顺序：`StudentEntry → Bootstrap → YardCrane → StudentHome → TeacherHome`。
  - 更新`YardCraneStudentShellVerification`为真实跨场景教师链，RenderTexture截图目标改为跟随当前UIDocument；更新StudentShell纯逻辑Harness及旧Lifecycle Harness的同场首页假设；新增`Tools/TeacherHomeUiHarness/Invoke-TeacherHomeUiChecks.ps1`。
  - Unity全工程首次刷新还暴露了与本任务无关但会阻断Play的6000.5 API残留：`YardCraneBootstrap`及四处Obi源码误用了固定工程Unity 6000.0.42f1不存在的`GetEntityId`。已恢复为该版本支持的`GetInstanceID`，未改动Obi行为。
- 实际验证环境：Windows，本机已打开的Unity `6000.0.42f1`；无NodeService、Gateway、PLC或外部教师平台；未构建Windows Player，未执行Git提交。
