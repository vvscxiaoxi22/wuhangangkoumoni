### 1.1 当前场景边界

```text
StudentEntry
├─ 学生端本机身份登记
├─ 学生训练入口与设备就绪提示
├─ 教师端本机身份登记
└─ 教师模块状态页（未接入能力明确标记，不伪造发布或成绩）

Bootstrap（DontDestroyOnLoad）
├─ 启动参数与场景生命周期
├─ 持久化 DrivingAndResultUI
├─ 驾驶 HUD / 操作指引
└─ Finalizing / ExitAllowed / Terminated / Failed 结果状态卡
        ↓ 单机模式加载
test（作业场景）
└─ 场桥 Rig、物理、输入与机构；只读适配器把反馈送往 Bootstrap UI
```

- `YardCraneBootstrap` 在自身对象下创建 `90_DrivingAndResultUI_UI Toolkit`，加载 `test` 后 UI 不再归 Rig 所有；直接 Play `test` 仍保留开发兜底挂载。
- 驾驶 UI 只读采样，不取得输入或机构控制权；PLC 仍只能由 `PortGatewayService` 持有，Unity 未新增 S7 连接。
- 结果卡只投影场景生命周期，不生成或猜测分数。正式评分仍须由 NodeService 完成原子终结后回传。

### 1.2 双屏规则

## 20. 真实Play报错：Lower UIDocument被Unity当成Upper的嵌套子面板，`PanelSettings`断言失败；已修复（交互会话）

- 任务状态：`根因已定位 / 修复已实施 / Unity Play复验未拿到`，不能标记完成。本任务在与用户的交互式Claude Code会话中直接处理（不经`Invoke-ClaudeTask.ps1`受控流程）。
- 用户提供真实Play报错：
  ```
  AssertionException: Assertion failure. Values are not equal.
  Expected: YC Student Shell Lower Runtime Panel (UnityEngine.UIElements.PanelSettings) == YC Student Shell Upper Runtime Panel (UnityEngine.UIElements.PanelSettings)
  ...
  UnityEngine.UIElements.UIDocument.set_panelSettings (...)
  PortTraining.YardCraneSimulator.Shell.YardCraneStudentShell.BuildLowerInterface () (at Assets/YardCraneSimulator/Runtime/Shell/YardCraneStudentShell.cs:268)
  ```
  这是第17节双屏改造以来第一次拿到真实Unity Play证据——同时也证明前面第18、19两节纯文件系统层面的搬迁（撤销Package化、按Display分组）没有引入新的编译错误，工程已经能跑到`OnEnable→BuildInterface→BuildLowerInterface`这一步，只在这一处运行时断言失败。
- 根因：Unity的`UIDocument`组件会在`Transform`层级里自动检测"我的GameObject是不是另一个挂了`UIDocument`的GameObject的子物体"——如果是，Unity把这种情况当成官方支持的"嵌套子面板"（子UIDocument的可视化树会被挂进父UIDocument的树里），并**强制要求子UIDocument的`PanelSettings`必须和父UIDocument完全一致**，赋值不一致的`PanelSettings`就会在`set_panelSettings`内部触发`Assert.AreEqual`失败。
  - 第17节`BuildLowerInterface()`里Play模式分支写的是`lowerHost.transform.SetParent(transform, false);`——`transform`就是`YardCraneStudentShell`组件自身所在的GameObject，也正是Upper `UIDocument`（`document`）所在的那个物体。这就把`lowerHost`变成了Upper UIDocument所在物体的子物体，被Unity误判为"Lower是Upper的嵌套子面板"，进而强制两者`PanelSettings`必须相同——但Upper、Lower设计上必须是两个完全独立、分别渲染到Display1/Display2的顶层面板，各自的`PanelSettings`（`targetDisplay`不同）本来就应该不一样，二者矛盾，断言必然失败。
  - 顺带确认：编辑器预览分支（`editorPreviewRootLower`，非Play模式走这条）当初就没有做这个`SetParent`，只用`SceneManager.MoveGameObjectToScene`把它挪到当前场景，是独立根物体——这条分支本来就没有这个bug，只有Play模式这一条分支有问题，属于两条分支实现不对称导致的遗漏。
- 实际修复：`Assets/YardCraneSimulator/Runtime/Shell/YardCraneStudentShell.cs`的`BuildLowerInterface()`，Play模式分支删掉`lowerHost.transform.SetParent(transform, false);`，改成跟编辑器预览分支一致的写法——`SceneManager.MoveGameObjectToScene(lowerHost, gameObject.scene);`，让`lowerHost`保持独立根物体，不挂在Upper UIDocument所在物体下面。补充了解释这条限制的注释，避免以后又有人顺手把它挂回`transform`底下。背景相机（`EnsureBackgroundCamera`）挂在`lowerHost`下面这一层不受影响——Camera不是`UIDocument`，不会触发这条嵌套面板检测。
