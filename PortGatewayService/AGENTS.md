# PortGatewayService 开发约束

> 2026-09-15 场桥范围更正：本目录及下列约束仅作为历史Gateway实现与证据维护。`PortGatewayService`已经退出当前`YardCraneSimulator`的S7交付路径；场桥唯一允许持有game4automation S7直连组件的位置是独立场景`Assets/YardCraneSimulator/Scenes/YardCraneS7Integration.unity`。不得再把本目录作为当前场桥PLC开发入口，也不得把旧Gateway测试继承为场桥直连验收结果。

## 工程定位

- 历史设计中，本工程曾被定义为港口实训平台唯一的S7 PLC连接持有者；该约束自2026-09-15起不再适用于当前场桥交付链。
- 历史一期设计对上通过本机Windows Named Pipe，向学生端提供控制租约、诊断、配置校验与安全事件（`pt.gateway.control.{stationId}`），向场景EXE提供设备输入帧与仿真反馈帧（`pt.gateway.realtime.{stationId}`）。
- 历史一期设计对下通过S7 TCP与PLC通信，对单台PLC只维持一条长连接。
- 当前目录保留协议基础骨架、模拟设备后端、管道Harness及历史验证证据，状态为`历史部分实现/退出当前场桥路径`；不得描述为已上线的完整服务。

## 必须遵守

以下约束仅适用于维护历史Gateway实现，不得据此把Gateway重新接回当前场桥交付路径：

- 对单台PLC只维持一条长连接，不得为不同调用方各自开连接。
- PLC地址、DB号、偏移、数据类型和读写权限只存在于版本化点表配置中，不得硬编码在业务逻辑里。
- 必须批量读写连续数据区，禁止按每个点位建立独立请求。
- PLC急停、限位、控制断和硬件安全联锁始终优先，软件不得绕过或延迟响应。
- 真实S7驱动/库必须在目标PLC型号、固件和TIA配置上完成PoC后才能锁定选型；PoC完成前不得宣称PLC已接通。
- Named Pipe帧格式、管道命名和握手顺序（首帧必须是`protocol.hello`）遵循接口标准V1.1第3.2节，不得自定义新的本机通信协议。
- 跨软件消息模型最终统一引用`PortTraining.Contracts`（当前该包本身也是`未实现`）；在其落地前按V1.1文档字段实现，不得另造一套同名或语义冲突的契约。
- `session.prepare`必须原子化完成设备检查、操控方式锁定和租约授予，并持续监控学生端与场景双心跳。
- 不得提交PLC凭据、点表中的真实产线地址等敏感信息到仓库或日志。
- 新需求、架构决策、问题和验证结果必须追加到当天的讨论记录，不覆盖历史结论。

## 验证底线

- 代码任务至少完成目标工具链编译；涉及PLC或Named Pipe运行逻辑时必须再完成运行验证，编译成功不能单独视为验证通过。
- 跨软件接口验证必须覆盖与改动相关的成功、拒绝、超时、重复、断连和恢复路径。
- 未接入真实PLC前，只能做协议自检、模拟点表或回环测试，并在记录中明确标注为非真实PLC联调证据。
- 详细交付字段与状态定义遵循`../PortTraining/LM-Wiki/03-规则层/任务验证与文档交付规范.md`。

## 任务交付门禁

- 每个任务严格按`实现完成 → 验证通过 → 文档更新 → 才能交付`执行，任一阶段缺失不得宣称任务完成。
- 只完成编译或静态检查时，状态必须写为`实现完成 / 运行待验证`，不得写为`已完成`或`已验证`。
- 验证后立即更新当天讨论记录；架构、接口或长期规则变化时同步更新LM-Wiki知识层或规则层。
- 交接记录必须包含版本标识、修改文件、验证环境、实际执行步骤、关键日志、验收结论和未验证范围。
