# 2026-09-20 讨论记录

## 登录机型改为Inspector配置，并修复跨工程场景注册

### 背景

登录场景交付给其他工程后，学生登录时报`[YC_STUDENT_SHELL_HANDOFF_SCENE_MISSING] 'StudentHome' is not in Build Settings`。本机工程的Build Settings已包含五个正式场景；问题出在`.unitypackage`不会可靠携带或覆盖接收工程的`ProjectSettings/EditorBuildSettings.asset`，且代码中的字符串场景名不会让`StudentHome`自动成为`StudentEntry`的导出依赖。

用户随后调整机型配置方式：不再让学生在登录页选择场桥/岸桥，改由`YardCraneStudentShell`组件上的布尔字段配置；默认勾选为岸桥，取消勾选为场桥。同时要求删除登录组件对固定`StudentEntry`场景名的运行判断。

### 实现

- `YardCraneStudentShell`版本更新为`2026-09-20-yc-entry-shell-v30-inspector-crane-kind`。
- 新增Inspector字段`是否岸桥`（`IsQuayCrane=true`）：登录界面构建和提交登录时将其转换为`SelectedCraneKind`，单模式加载到`StudentHome`或`TeacherHome`后继续由静态状态选择对应任务资产。
- 删除运行时创建的`场桥系统/岸桥系统`按钮、事件绑定和相关就绪条件；登录页只保留学生/教师身份切换。
- 删除`YardCraneStudentShell`和其自定义编辑器中基于`gameObject.scene.name == "StudentEntry"`的生命周期/预览限制。`SceneName`常量仍用于学生端、教师端退出后返回登录场景，不再参与登录组件是否运行的判断。
- `StudentEntry.unity`显式序列化`IsQuayCrane: 1`以及学生/教师首页场景名，确保交付默认值为岸桥。
- `YardCraneBuildAutomation`增加域重载和场景导入后的增量注册：只追加或启用缺失的五个正式场景，保留接收工程的其他场景及相对顺序；提供`Tools/PortTraining/Yard Crane/Register Required Scenes`手动入口。Windows专用构建直接使用固定五场景数组，不再要求接收工程只有这五个启用场景。
- Play验证脚本同步改为断言Inspector机型配置生效且登录页没有机型选择控件。

### 验证

- Unity `6000.0.42f1`引用的真实Roslyn编译：Shell与相关Editor源码通过。
- `StudentHomeUiHarness`：`FINAL PASS checks=269 failures=0 warnings=2`。
- 完整`YardCraneSimulator.Editor`程序集使用当前Bee响应文件、重定向临时产物编译：`EDITOR_COMPILE_EXIT=0`。
- `StudentEntry.unity`已静态确认`IsQuayCrane: 1`；五个正式场景在本机Build Settings中均启用。

### 未验证范围

- 未启动Unity Play，Inspector取消勾选后的场桥路径、默认勾选后的岸桥路径以及学生/教师真实跳转仍需画面与交互验收。
- 尚未在一份全新的接收工程中导入重新导出的`.unitypackage`，因此自动增量注册的首次导入行为标记为待验证。

## 学生首页导包后缺少故障目录

### 现象与根因

接收工程可从`StudentEntry`正常跳转到`StudentHome`，但学生首页构建时报`YC_STUDENT_SIDE_SHELL_MISSING_ASSET`，提示缺少`YardCraneShell/StudentSide/Display1UI/StudentFaultCatalog`。故障目录原先只通过`Resources.Load`字符串路径读取；Unity导出场景并包含依赖时无法从该字符串建立GUID依赖，因此包内可能有场景和脚本却遗漏JSON。接收端日志仍使用旧错误文案，也说明当时导入的学生端Shell不是本次修复后的完整版本。

### 方案更正与最终实现

- `YardCraneStudentSideShell`版本更新为`2026-09-20-yc-student-home-v20-data-fault-assets`，分别增加岸桥、场桥两个`ScriptableObject`引用，通过只读反射适配既有`故障信息._故障`字典，不引用也不修改Data脚本。
- `StudentHome.unity`显式绑定岸桥资产GUID `c5bab4325aa08b241a586d6bc4b28597`和场桥资产GUID `5801956bc9248e94aa3c9f536a6e569d`；两份权威资产成为场景导出依赖。
- 运行时按`YardCraneStudentShell.SelectedCraneKind`选择单一资产：`QuayCrane`读取岸桥100项，`YardCrane`读取场桥90项；要求每条记录的`类型`属于页面既定8类，任一空类、重复/非法ID或结构不匹配都会给出明确构建错误。
- 学生端不再通过`Resources.Load`读取`StudentFaultCatalog.json`。教师端UI及`Assets/Data`中的脚本和资产内容均未修改。
- `StudentHomeUiHarness`改为直接解析两份Data资产，并断言两个场景字段的GUID和机型选择代码，防止再次回退为字符串资源加载。

## 更正：机型改由Build Profile宏确定，并接通训练场景分流

### 更正原因

用户将交付方式从登录组件Inspector布尔值调整为Unity 6 Build Profile的Scripting Defines。本文前文记录的`IsQuayCrane`方案是当时已实现的历史过程，不再代表当前代码；本节追加最终配置，保留前文作为变更证据。

### 当前实现

- `YardCraneStudentShell`版本更新为`2026-09-20-yc-entry-shell-v31-build-profile-crane-kind`，删除公开字段`IsQuayCrane`及`StudentEntry.unity`中的旧序列化值。
- `Mode_Anqiao`编译为`QuayCrane`，`Mode_Changqiao`编译为`YardCrane`；同时定义两者会触发`#error`。未定义任一宏时继续使用旧交付的岸桥默认值，并在Play首次应用配置时输出`YC_CRANE_MODE_DEFINE_MISSING`，避免接收工程因未创建Build Profile而无法导入。
- `SelectedCraneKind`在静态初始化时直接采用构建配置，因此即使直接打开`StudentHome`或`TeacherHome`，也不会先读到另一个机型的硬编码默认值。登录就绪日志增加`craneSource`，可直接确认宏来源。
- `StudentHome`序列化两个训练场景字段：场桥默认`YardCrane`，岸桥默认`港口场景`。学习训练的实际启动按钮、自由练习和任务考核最终都进入同一个`BeginTraining`，按`SelectedCraneKind`选择场景。
- 训练仍先进入`Bootstrap`，没有绕过原有会话、生命周期和导航链。目标场景请求与当前训练`SessionId`绑定，在Bootstrap中一次性消费；启动异常会清除请求、导航桥、训练会话和身份，避免旧请求串到下一次训练。
- Build Settings及自动注册逻辑在五个必需业务场景之外，会在`Assets/Scenes/港口场景.unity`存在时把它追加并启用。没有修改`Assets/Data`脚本/资产，也没有修改教师端UI。

- 当前Unity编辑器检测到改动后重新生成`YardCraneSimulator.Shell.dll`与`YardCraneSimulator.Editor.dll`，时间为2026-09-20 04:21:43；Editor日志未出现`error CS`。
- `git diff --check`针对本次脚本、场景、Build Settings和Harness路径通过。

### 未验证和功能边界

## 教师直启admin与统一当前试卷Data链路

### 需求与决策

用户要求直接播放`TeacherHome`时默认使用`admin`，不再返回登录页；同时新增一份仿照`任务State`的Data，用来表示老师当前唯一发布的试卷。故障考核保存故障ID，实训考核保存完整任务字段；学生点击“任务考核”时再把当前试卷复制进`任务State.asset`。

现有实训、故障发布记录仍由`LocalTrainingData`中的JSON Store持久化。运行时修改包内ScriptableObject不能跨独立Player进程或重启写回资源，因此新Data定位为当前运行期镜像；学生入口会从JSON发布记录重新生成镜像，避免必须先进入教师场景。

- `YardCraneTeacherSideShell`没有登录交接时调用现有本地认证建立`admin/admin`教师身份；返回登录按钮隐藏，旧`Logout()`也不再加载`StudentEntry`。教师发布、重新发布、取消发布、删除，以及编辑当前已发布实训任务后，都会刷新当前试卷Data。

## Shell UI取消运行时PanelSettings克隆

### 原因与实现

用户要求UI不再动态生成面板配置，直接使用对应文件夹中的`StudentShellUpperPanel.asset`等PanelSettings资源，以便由资源本身统一控制分辨率自适应。静态核对确认三个场景的`UIDocument`和UXML原本就是场景序列化持有；运行时动态生成的实际是PanelSettings克隆，学生首页与教师首页还会每帧写缩放并固定根画布尺寸。

- `YardCraneShellPanelUtility.PrepareDocument()`改为验证并直接绑定Inspector中的PanelSettings资源，不再`Instantiate`、设置`HideAndDontSave`或在释放时销毁面板。
- `StudentHome`和`TeacherHome`删除运行时`ScaleDisplayCanvas()`及每帧缩放调用，不再写共享资源的`scale`，也不再强制根节点`width/height/left/top`。`StudentEntry`保留横竖屏USS类切换，但不写PanelSettings。
- 三个场景的上下屏继续各用独立PanelSettings；六份资源全部改为`Scale With Screen Size`、`Shrink`、参考分辨率`1920×1080`，并保留上屏`targetDisplay=0`、下屏`targetDisplay=1`。
- 未修改`StudentEntry.unity`、`StudentHome.unity`或`TeacherHome.unity`，未修改Data脚本、任务/试卷链和教师端业务界面。

### 验证与边界

- 定向搜索确认Shell目录中不再存在PanelSettings实例化、`panel.scale`、`targetDisplay`或`targetTexture`运行时写入。
- 当前Unity编辑器开启，为保护未保存现场未自动执行Play。多分辨率缩放、非16:9留白、双屏显示和点击命中仍需画面验收；单显示器环境下指向Display2的下屏不会自动回退到Display1。

## 更正：教师多题组卷与学生逐题进入考核

### 需求与最终数据模型

用户将教师端任务管理调整为一套可包含多道题的试卷：单项操作、联动操作等实训项目可以多选，故障排除条目也可以多选；每个所选项目进入任务管理列表成为一条独立题目。题目行首勾选框是发布开关，所有已勾选题目共同构成当前学生试卷，不再沿用“全局只能发布一条任务”的旧模型。

- 新增统一考核题库/试卷Store，按当前Build Profile机型分别保存场桥与岸桥数据。持久化文件位于`LocalTrainingData/TeacherTasks/`，文件名分别使用`yard-assessment-question-bank.json`、`yard-assessment-paper.json`及`quay-assessment-question-bank.json`、`quay-assessment-paper.json`。
- 教师选择实训项目或故障条目后，系统把每一项作为独立题目加入对应机型题库；新题默认未勾选。教师在任务列表切换行首勾选框时立即重建当前paper，未勾选题仍保留在题库中，便于后续重新组卷。
- 训练题保存启动所需的完整任务快照；故障题保存故障编号及内部组卷信息。学生可读paper格式升级为v2，生成快照时强制清空故障答案字段`faultPoint`与`lineTag`，避免把故障点和标号直接下发给学生。
- 读取旧v1 paper时会就地清空答案字段、重新验证，并以原子写入方式升级为安全的v2；v1文件不会继续作为学生题目列表的数据返回。
- 本轮考核链不再读写`Assets/Data/Resources/试卷类型.asset`。该资产及此前实现保留为历史记录，但不再代表当前组卷、发布和选题链路。

### 学生端交互与任务State投影

- 学生点击首页“任务考核”后进入新增的考核题目列表页，页面按当前场桥/岸桥Build Profile只读取对应的当前paper；没有已勾选题目时不会启动训练场景。
- 学生选择一道实训题后，系统在场景加载前把该题的训练快照直接写入`Assets/Data/任务State.asset`；选择一道故障题时只把该题的故障ID写入任务状态，学生列表不显示`faultPoint`或`lineTag`。
- 故障考核统一使用600秒时长。所选题写入成功后直接进入对应的场桥或岸桥训练场景，不先闪回学生首页。
- 一道题完成并返回`StudentHome`后，学生可以再次点击“任务考核”，重新读取当前paper并选择下一题；当前设计不在进入第一题时消费或删除整套试卷。

### 验证、现场保护与剩余边界

- 教师端、学生端静态Harness均完成C#编译检查；题库多题添加、行首勾选后paper题数变化、学生题目列表、单题启动投影以及paper v2答案字段剔除均纳入静态契约。
- 当前学生Harness只剩1项已知失败：`StudentHome.unity`中`QuayCraneSceneName`仍序列化为`YardCrane`，与预期岸桥场景不符。检测到Unity锁文件且可能存在未保存现场，因此本轮没有在外部改写场景；需要用户在Unity Inspector中设置真实岸桥场景名、保存`StudentHome`后复跑Harness。
- 未自动执行Unity Play。教师跨类别多选、行首勾选即时发布、学生列表点击、`任务State.asset`实际变化、故障题600秒以及完成后返回首页再选题，仍需人工运行验收。
- 目标训练场景目前对所有题目仍统一使用`PickupWorkflow`。本轮闭合了题库、组卷、发布、选题和状态投影，没有扩展各实训项目的专用动作流程，也没有实现故障注入、故障专项判定或正式题型评分；这些仍是后续业务闭环工作。

### 补充：DHCP摄像机单路凭据验证

- 用户后续指定截图中的一台`DS-2CD2D45DWD/M`先做连接测试。截图旧地址为`192.168.1.65`，但该地址当前不可达；ARP确认其MAC同时对应当前网段的`192.168.199.70`，说明设备启用DHCP后已迁移到`.199.70`。
- `.199.70`的Ping成功，TCP `80/554/8000`均开放。使用用户提供的凭据分别执行RTSP Digest `DESCRIBE`和海康ISAPI HTTP Digest设备信息请求，均返回`401 Unauthorized`，HTTP明确返回`Login denied`。
- 为避免触发海康登录锁定，确认两种协议均拒绝后停止继续尝试。密码未写入命令行、JSON、源码、日志或Windows凭据管理器；测试期间只经隐藏标准输入进入进程内存并在结束时释放。
- 结合此前设备列表中该序列设备显示“未激活”，当前最可能是管理员密码尚未在设备上成功激活/应用，或用户提供的密码并非该设备当前密码。需先在海康工具中完成激活或确认实际管理员密码，再继续SDP与解码验证。
- 本机忽略配置中的`feed1`已指向设备当前DHCP地址`.199.70`、RTSP端口554和102子码流；凭据验证成功前不启动重复重连。

- 用户确认已完成设备激活后，再次使用系统curl的原生HTTP Digest实现访问`.199.70`的`/ISAPI/System/deviceInfo`，结果仍为`401`且curl明确报告`Login denied`。这排除了“仅因设备未激活而拒绝”的单一解释；当前管理员密码尚未实际生效、输入与激活时不一致，或设备账号已进入临时锁定状态。为避免增加失败计数，本轮未继续尝试RTSP或其他接口。
