# 港口实训平台项目开发基线

- 基线日期：2026-08-28
- 适用范围：港口实训平台全部软件，而不只是当前学生端工程
- 当前学生端 Unity 版本：6000.5.5f1
- 当前场桥场景 Unity 版本：6000.0.42f1
- 目标运行平台：Windows 64 位
- 文档状态：当前开发与设计的统一入口；跨软件实现以[接口标准V1.1](跨软件接口与参数标准-v1.1.md)为准

## 1. 文档目的与使用规则

本文件把截止当前已经确认的产品思路、业务逻辑、软件边界、通信方式、一期范围、UI原则和开发顺序汇总为一份可执行基线。后续开发任何一个软件前，先确认本文件中的职责边界和公共契约，避免学生端、教师端、Gateway、岸桥场景和场桥场景分别形成互不兼容的实现。

信息优先级如下：

1. 当前用户明确确认的决策和当天讨论记录。
2. 《岸桥场桥项目技术要求2026.8.14》中的强制验收要求。
3. 当前代码所反映的真实实现状态。
4. 早期总体规划和参考产品手册。

当早期规划与当前决策冲突时，以本基线为准，并在原始资料层保留历史方案，不覆盖历史事实。

功能状态统一使用：`已实现`、`部分实现`、`未实现`、`当前阶段不开放`。界面存在、按钮可点或存在模拟数据，不等于功能已实现。

## 2. 项目定位

本项目不是单独制作一个起重机三维演示程序，而是建设一个模拟真实港口业务的虚实结合实训平台：

- 教师或TOS形成标准作业工单。
- 学生以岸桥司机或场桥司机身份登录并执行任务。
- 学生既可使用电脑键鼠进行桌面模拟，也可在实体模拟机上使用不同机型的操控台和PLC。
- 岸桥、场桥驾驶场景独立全屏运行，管理平台负责任务、设备检查、启动、结果和档案。
- 本地操作和ROCS远程操控使用同一业务任务，但使用不同输入配置和视景配置。
- 单人训练、两名司机联合作业、无教师电脑运行和未来TOS接入共用一套任务生命周期。

一期岗位只覆盖岸桥司机和场桥司机。AGV在一期是受任务调度的系统角色，不设置AGV司机学生岗位；AGV负责连接岸桥与场桥的水平运输环节。

## 3. 一期软件清单

一期按六个可独立部署的运行单元开发，另预留一个后续适配服务。

### 3.1 PortTraining 学生端

技术形态：Unity 6000.5.5f1 Windows客户端。

主要职责：

- 学生登录、岗位和工位识别。
- 工作台、任务中心、训练档案、学生画像和设备设置。
- 同时支持`DesktopSimulation`与`SimulatorCabin`部署模式。
- 接收教师、本地缓存或TOS转换后的标准工单，不直接访问生产TOS。
- 创建唯一`operationRunId`，完成开始前检查。
- 启动对应岸桥或场桥场景EXE，并等待场景`Ready`回执。
- 与场景和Gateway保持运行心跳，接收完成、终止和异常结果。
- 幂等保存任务状态、训练记录和学生画像。

不负责三维驾驶场景渲染、直接实现S7协议、持有PLC连接、解释PLC DB地址或裁定联合作业全局阶段。

### 3.2 PortTeacher 教师端

技术形态尚待最终选定，可采用本地Web管理端加本地服务并打包为Windows安装程序。无论采用何种界面技术，一期功能契约不变。

主要职责：

- 教师登录和权限管理。
- 工位、学生和在线状态总览。
- 新增、复制、编辑、校验、预览、发布和撤销任务。
- 管理正式作业、联合作业、排故实训、自由练习模板。
- 设置机型、作业类型、源位置、目标位置、箱型、车道、AGV/集卡、控制模式、执行窗口和分派工位。
- 监控任务准备、启动、执行、暂停、终止和完成状态。
- 查看训练档案、问题事件、评分数据和导出结果。
- 作为TOS任务收件箱，查看原始业务任务、映射状态、校验结果并审批生成教学任务。
- 在同机部署和局域网部署下提供相同业务能力。

一期必须开发教师端。考核中心的完整交互当前阶段可不开放，但任务编辑、发布、状态监控和结果查看不能因此缺失。

### 3.3 PortTrainingNodeService

技术形态：.NET本地后台服务，同一个程序包支持`Authority`和`Edge`两种角色。

主要职责：

- Authority负责用户、模板、工单、运行和结果的最终裁决。
- Edge部署在每台学生电脑，负责本机缓存、运行日志、durable outbox、自由练习和授权离线任务。
- 提供教师端和学生端共同使用的HTTPS REST、WebSocket、SQLite存储、事件补拉和同步服务。
- 联合作业协调节点由签名工单指定，两个Edge断网后禁止自动选主。

### 3.4 PortGatewayService

技术形态：建议使用.NET开发为无界面本机后台进程或Windows服务，不使用Unity开发。

主要职责：

- 独占本工位PLC的S7长连接。
- 按固定周期批量读取和写入点表数据。
- 把PLC地址转换为统一设备语义，把仿真反馈转换回白名单PLC写入区。
- 管理`operationRunId`控制租约，只有当前运行可以发送控制帧。
- 执行断线重连、序号、时间戳、数据新鲜度、心跳和版本握手。
- 强制执行本地/ROCS模式锁定。
- 场景崩溃、心跳超时、PLC掉线或急停时清零控制输出并释放租约。
- 向学生端提供只读诊断状态。

当前代码中的`EmbeddedGateway`只作为模拟输入和接口验证原型，后续应迁移为独立服务适配层，不能作为生产S7最终实现。

### 3.5 QuayCraneSimulator 岸桥场景

技术形态：独立Unity Windows EXE，全屏运行。

主要职责：

- 65吨岸桥及真实作业场地1:1三维场景。
- 大车、小车、起升、前大梁俯仰、吊具倾转/回旋、导板、中锁和20/40/双20尺逻辑。
- 装船、卸船、单项、联动、能力提升、自由练习和排故现象呈现。
- 就地驾驶室和ROCS远程视景。
- 生成碰撞、越限、对位、着箱、锁销、效率、流程和安全事件。
- 向学生端提交训练结果，不直接修改学生档案。

### 3.6 YardCraneSimulator 场桥场景

技术形态：独立Unity Windows EXE，全屏运行。

主要职责：

- 40.5吨场桥及真实堆场1:1三维场景。
- 大车、小车、起升、吊具回旋、夹轮器、吊具泵和20/40尺逻辑。
- 收箱、提箱、海侧内集卡/AGV转运、陆侧外集卡作业和堆场箱位管理。
- 单项、联动、能力提升、自由练习和排故现象呈现。
- 就地驾驶室和ROCS远程视景。
- 生成对位、扫桩、障碍摆箱、碰撞、流程和安全事件。

### 3.7 PortTosAdapter（预留扩展）

TOS适配器不是一期学生操作入口，但公共契约必须在一期预留。它负责：

- 从TOS沙箱、培训租户或只读镜像拉取/订阅任务。
- 幂等去重并转换为平台标准作业指令。
- 完成船舶贝位、堆场箱位、车道和场景坐标映射。
- 把任务送入教师端TOS收件箱，按授权规则人工审批或自动发布。
- 回传训练状态和仿真摘要；未经书面授权不得写入生产TOS真实完工状态。

TOS不能访问Unity、PLC或Gateway，也不能直接发送运动控制命令。

## 4. 共享运行组件

以下能力应作为共享库或后台组件复用，不各自在六个运行单元中重新定义：

- `PortTraining.Contracts`：消息模型、枚举、错误码和版本号。
- PortTrainingNodeService已经是明确部署单元；共享层只保留它使用的数据库Schema、同步协议和客户端SDK。
- Scene Launcher：外部EXE路径、启动参数、版本握手、超时和崩溃检测。
- Operation Coordinator：`operationRunId`、状态机、控制租约和幂等结果。
- Task Package Import/Export：离线任务包、签名、版本和导入审计。
- Discovery：局域网教师节点和学生节点发现。

共享契约应有独立版本，六个运行单元不能通过复制类文件维持兼容。

## 5. 部署与离线运行

### 5.1 教师端与学生端在同一台电脑

- 同一个PortTrainingNodeService实例以Authority+Edge组合角色监听回环地址。
- 学生端通过回环地址同步任务和回传结果。
- Gateway、学生端和驾驶场景均在本机运行。
- 无外网不影响登录、本地任务、场景启动和结果保存。

### 5.2 教师端与学生端为多台电脑

- 教师电脑的PortTrainingNodeService作为Authority，各学生电脑运行Edge。
- 学生端使用HTTP API同步业务数据，使用WebSocket或等价通道接收状态更新。
- 学生端缓存已下达任务；教师端暂时离线时，已缓存且允许离线执行的任务仍可完成。
- 网络恢复后按版本和幂等键补传状态与结果。

### 5.3 只有两台学生电脑，没有教师电脑

两台学生电脑必须同时支持：

- 各自连续自由练习。
- 各自执行已缓存或离线导入的独立任务。
- 执行此前由教师发布并允许离线运行的任务。
- 组成岸桥司机与场桥司机联合作业。

联合作业时，由Authority签名工单预先指定一个Edge为本次`operationId`协调节点。两节点网络分区后双方暂停，禁止自动提升协调者；更换协调节点必须取得Authority签发的新`coordinationEpoch`，或者终止旧运行后重新开始。

## 6. 统一业务模型

### 6.1 核心标识

- `taskTemplateId`：任务模板。
- `taskVersion`：模板或任务快照版本。
- `workOrderId`：分派给一个岗位/工位的工单。
- `operationId`：一次完整港口作业；联合作业的岸桥和场桥子工单共享该ID。
- `operationRunId`：某学生实际进入驾驶场景的一次运行，每次重试都不同。
- `studentId`：学生身份。
- `stationId`：实体或桌面工位。
- `machineType`：`QC`或`YC`。
- `controlMode`：`Local`或`Remote`。

所有启动、心跳、控制、事件、告警和结果消息至少携带`operationRunId`、`workOrderId`、`studentId`、`stationId`、序号和采集时间。

### 6.2 工单来源

平台统一处理教师任务、本地自由练习/离线任务包、TOS导入后生成的教学任务。TOS可以视为自动任务发布者，但必须经过平台校验、映射和授权规则，不能绕过教师端任务生命周期。

### 6.3 学生操作流程

学生端取消无意义的“接收工单”步骤：

```text
登录
→ 首页查看当前任务
→ 必要时进入任务中心切换任务
→ 点击一次“进入驾驶室”
→ 自动完成设备与版本检查
→ NodeService创建operationRunId并签发RunTicket
→ Gateway原子复核设备、锁定模式并预留租约
→ 注册场景令牌摘要并启动对应场景EXE
→ 场景完成学生端与Gateway双握手
→ 场景返回Ready和Started后进入Running
→ 完成或异常终止
→ 幂等写入结果
→ 返回学生端查看训练档案和学生画像
```

任务中心不是独立的多余流程，而是正式作业、联合作业、排故实训和自由练习的统一目录。首页保留当前任务和“一步进入驾驶室”入口。

### 6.4 教师任务流程

```text
新建/复制/TOS导入
→ 编辑草稿
→ 校验机型、箱型、源/目标位置、车道、车辆、场景和评分版本
→ 预览
→ 分派学生或工位
→ 发布
→ 学生同步或离线缓存
→ 监控准备/运行/异常
→ 接收结果
→ 查看档案、复盘和导出
```

已发布且已经开始的任务不可原地修改。修改时复制为新版本，历史运行始终关联原快照。

## 7. 装卸船、车道、AGV与联合作业

### 7.1 岸桥任务

- 卸船：船舶`Bay/Row/Tier` → 岸桥作业车道上的AGV或内集卡。
- 装船：岸桥作业车道上的AGV或内集卡 → 船舶`Bay/Row/Tier`。
- 每个任务必须明确船舶/泊位、箱位、箱号、箱型、重量、车号、车道和到位窗口。
- 装卸船任务支持20尺、40尺和双20尺；车道选择和船舶工况必须配置化。

### 7.2 场桥任务

- 卸船转堆：海侧AGV/内集卡作业位 → 堆场`Block/Bay/Row/Tier`。
- 装船出堆：堆场箱位 → 海侧AGV/内集卡作业位。
- 收箱：陆侧外集卡 → 堆场箱位。
- 提箱：堆场箱位 → 陆侧外集卡。
- 每个任务必须明确海侧或陆侧、车号、车位/车道、堆场箱位和交接条件。

### 7.3 AGV职责

AGV不是随意背景车辆，而是任务实体：接收调度、上报到位和运输状态，箱体交接由吊具释放、车辆在位和任务阶段共同确认。岸桥司机和场桥司机不能直接改变AGV目标位置。

### 7.4 岸桥与场桥联合作业

联合作业使用同一个`operationId`，但生成两个独立`workOrderId`：

```text
岸桥卸船子工单
→ 箱体交给AGV
→ AGV运输
→ 场桥卸车入堆子工单
→ 全局作业完成
```

装船流程反向执行。任何一方完成自己的子工单，不代表全局作业已经完成。协调节点负责全局状态，学生端只展示与本岗位相关的当前阶段和等待原因。

## 8. 控制与通信架构

```text
PortTeacher / PortTrainingNodeService / TOS Adapter
                    │ 任务与结果
                    ▼
              PortTraining
             ┌──────┴──────┐
       本机IPC             本机IPC
             ▼              ▼
PortGatewayService     QC或YC场景EXE
             │              │
             └──实时语义帧──┘
             │ S7 TCP
             ▼
            PLC
```

### 8.1 为什么Gateway独立

- S7连接只有一个持有者，避免学生端和场景竞争PLC。
- 驾驶场景崩溃时，独立服务仍能撤销控制并清零输出。
- QC和YC场景使用同一语义协议，不引入PLC库。
- 本机IPC延迟通常远低于PLC扫描和轮询周期，不是主要瓶颈。
- .NET后台服务更适合通信、重连、日志、服务自启和无界面部署。

### 8.2 模式锁定

技术要求中的“可切换就地/远程”解释为：任务开始前允许选择任务支持的`Local`或`Remote`；Gateway在`session.prepare`的同一临界区内重新检查设备并锁定模式；`Running`期间不允许切换。若检测到实体台位或任务模式变化，租约立即失效，必须暂停或终止并创建新运行。

### 8.3 开始前检查

进入驾驶场景前至少检查：

- 学生、岗位和工位匹配。
- 任务机型、场景版本和点表版本匹配。
- Gateway在线且PLC通信新鲜。
- 急停已复位、控制电源状态正确、手柄回中。
- 控制模式与实体台位一致。
- 当前工位没有其他活动运行。
- 联合作业参与者和协调节点满足开始条件。

场景未返回`Ready`前，工单不能进入`Running`。

## 9. 学生端信息架构与UI基线

### 9.1 登录页

- 只保留必要登录框，不展示过多产品说明。
- 背景采用蓝色港口主题的治愈系、莫兰迪、朦胧颗粒插画。
- 登录框与背景的颜色、材质和空间关系必须统一。
- 当前离线登录只是长度校验，正式身份认证仍需实现。

### 9.2 首页

- 当前任务和一步进入驾驶室。
- 学生画像：任务完成率、累计练习时长、平均成绩、安全操作率。
- 最近训练、待办提醒和必要的联合作业等待状态。
- 底部设备状态栏展示Gateway、PLC、工位、急停和输入源。
- 不展示意义弱的任务来源/作业方式/训练环境信息卡，也不使用装饰性Slider填充空间。

### 9.3 任务中心与训练档案

- 任务中心统一承载正式作业、联合作业、排故实训和自由练习。
- 学生选择任务后直接设为当前任务，不再增加“接收工单”动作。
- 考核筛选和考核中心在当前阶段置灰。
- 训练档案展示真实履历、时长、完成情况、评分、安全率和问题事件。
- 五维能力为安全规范、操作精准、作业效率、流程规范、协同能力。
- 数据只能来源于已提交运行结果，不能生成演示假成绩。

### 9.4 设备与S7设置

- 提供工位、部署模式、Gateway地址、PLC配置、点表版本、输入设备和显示配置的查看与修改入口。
- 普通学生只读；管理员修改后需校验并记录审计。
- 训练启动后禁止修改PLC、点表、机型和控制模式。
- 当前UI只有导航入口，功能页面尚未形成闭环。

## 10. 驾驶场景UI基线

驾驶场景是独立全屏程序，不嵌入学生管理端。

- 支持桌面16:9显示配置和实体设备9:16竖屏配置。
- 竖屏中状态信息集中在上半部左右两侧，下半部保持无信息遮挡，保留吊具和落箱区域视野。
- 顶部任务提示采用更窄的轻量条，不占据主要视野。

## 11. 技术要求验收基线

最终合同验收不能只按当前UI阶段判断，至少需要满足：

- 岸桥参照65吨机型、场桥参照40.5吨机型，真实场地1:1建模。
- QC和YC均支持就地操作、ROCS远程操控和电气排故。
- 岸桥五类实训不少于15个子项目；场桥五类实训不少于16个子项目。
- 岸桥支持装船/卸船、20/40/双20尺、车道和船舶贝位配置。
- 场桥支持收箱、提箱、装船转运、卸船转堆和堆场箱位配置。
- QC和YC分别建立不少于48个真实电气故障点，并支持同时设置至少两处故障进行排故考核。
- 教师端和学生端均有用户与任务流程，训练结果可评定、记录和导出。
- 预留真实港口业务系统和数字孪生系统双向接口并形成安全隔离。

当前“考核中心置灰”是开发阶段取舍，不代表合同验收永久取消考核功能。恢复考核前必须先完成运行ID、结果幂等、评分版本锁定和异常处置。

## 13. 推荐开发顺序

### P0：场桥单机全流程模拟

自2026-09-01起，`YardCraneSimulator`调整为最高优先级。场桥必须先支持直接运行，并由键盘或Xbox手柄完成卸船转堆、装船出堆、陆侧收箱和陆侧提箱四类全流程作业。

输入设备、操作语义、作业安全联锁和机构运动必须解耦。键盘、Xbox和未来Gateway/PLC只负责生成统一操作语义，不能直接修改机构Transform、Rigidbody或绳索状态。

完成标准：不依赖学生端、教师端、NodeService和PLC，独立`YardCraneSimulator.exe`可以完成四类任务，支持正常、拒绝、急停恢复、本地结果和重新开始；键盘与Xbox使用同一套机构和业务逻辑。

### P1：真实模型、PLC和平台接入

- 导入1:1场桥与堆场模型并完成绑定、碰撞和性能验收。
- 建立Contracts、Named Pipe、Scene Launcher、NodeService和教师端最小闭环。
- 建立独立`PortGatewayService`并完成真实S7、点表和操控台联调；PLC语义接入场桥统一输入接口，不重写运动代码。

完成标准：教师可发布场桥工单，学生端启动同一个场桥EXE；桌面输入或PLC输入均能执行，结果可回传和恢复。

### P2：岸桥和联合作业

- 岸桥完成船舶抓箱 → 岸桥车道AGV放箱 → 结果提交的卸船闭环，再扩展装船、ROCS和训练项目。
- 实现AGV系统角色及岸桥、AGV、场桥同一`operationId`的装卸船联合作业。
- 验证只有两台学生机、没有教师电脑时的独立和联合任务。

### P3：排故、考核和TOS

- 两机型真实电气故障题库和故障板联调。
- 恢复考核中心、评分版本和成绩单。
- TOS沙箱任务导入、教师审批、执行和结果回传。
