# 2026-09-11 讨论与开发记录

## 1. StudentHome 三入口到 YardCrane 的本地训练逻辑闭环

### 1.1 目标与边界

- 用户要求学习训练、自由练习和任务考核三个入口都能进入正式 `YardCrane` 场景，并根据入口进入不同的运行模式，最终能够安全返回原页面。
- 三种模式统一经过 `StudentHome → Bootstrap → YardCrane`，复用正式场景中已有的两个 Camera 和唯一 `UIDocumentDisplay1`；运行时不动态创建 `UIDocument`。
- 本轮只建立本机训练闭环，不连接 PLC/S7，不伪装教师平台任务。任务考核为本地模拟考核，固定 `Unscored`、`isOfficial=false`，不生成正式成绩。
- 当前学生端版本：`2026-09-11-yc-student-home-v11-resilient-three-mode-loop`；训练协调器版本：`2026-09-11-yc-local-training-mode-v1`；审计格式：`2026-09-11-yc-training-score-v5-identity-correlated`。

### 1.2 实际实现

1. 新增不可变的本地训练会话上下文，冻结 `sessionId`、学生身份、模式、练习项目、目标值、计时策略、辅助等级、成绩可信等级、HUD 文案和返回页，场景切换后仍使用同一上下文。
2. 自由练习为开放式正计时模式，不设置目标、时限或引导；主动返回或退出只写本地中止审计，`hasScore=false`、`totalScore=0`。
3. 学习训练五类项目已连接真实目标判定：大车位置 `-6/-3/+3/+6 m`，小车位置 `-3/+1.5/+3 m`，吊具高度相对起点 `+1/-1/-2 m`，吊具水平回旋 `-3/+3/-1°`，吊具回零使用自动回零或回零后稳定保持 `1.5 s`。完成判定要求实际动作、进入容差并稳定保持；回零项目还要求先离开零位，再返回零位。
4. 本地任务考核为 10 分钟倒计时，按“锁定目标箱 → 带箱起升 → 带箱大车或小车转运 → 落箱稳定 → 解锁交箱”顺序推进；超时或顺序错误可失败，通过或失败都仅写 `Unscored` 本地审计。
5. 三种模式进入后均先执行 3 秒倒计时。倒计时只门禁运动和业务命令，心跳、控制电源、急停及故障复位通道保留；倒计时结束后协调器和 HUD 共享同一个单调计时原点。
6. 正式驾驶 HUD 根据模式显示任务、目标、计时和状态。七类居中弹窗继续覆盖在常驻 HUD 上方，弹窗之间互斥，出现时不隐藏驾驶 HUD；错误确认文案改为“我知道了”。
7. 返回链路按模式恢复页面：学习训练返回 `LearningSelection`，自由练习和本地考核返回 `StudentHome`。返回采用“预加载首页但不激活 → 输入门禁 → 结束生命周期/移交状态 → 卸载作业场景 → 激活首页 → 清理上下文”的事务顺序。
8. 启动和返回均增加失败回滚。若 `YardCrane` 未加入 Build Settings 或加载失败，Bootstrap 记录显式启动失败，桥接器自动回到发起页并显示一次性错误提示；该启动失败不会被误判为考核失败。
9. Bootstrap 改为唯一活动实例，并捕获本次 `trainingSessionId`；完成、中止、失败只允许更新匹配的会话，避免旧 Bootstrap 或旧回调污染新会话。场景导航桥、Rig、HUD 适配器和模式协调器均绑定当前活动实例。
10. 审计格式 v5 分离“本次冻结身份”和“运行时观察身份”，写入 `identityContextMatched`。身份不匹配时清空主要归属字段并保留观察字段，避免把运行结果错误归到另一名学生；正式成绩索引仍不写入。
11. 场景移交为单次消费；返回提示也只消费一次。`UIDocument` 因编辑器或面板生命周期重建时保留当前页面，不会把训练选择页无条件重置为首页。

## 2. 驾驶 Rig 真实尺度重标定：425m 大车 / 30m 小车 / 24m 结构高度 / 41 吨额定载荷

### 2.1 目标与边界

- 用户给出该堆场一列的真实尺度：大车方向（海侧小车停车点到路侧小车停车点）425m、小车跨度 30m、每侧 AGV 车道 4 条、大车车道 1 条、大车结构高度 24m；随后贴出真实 RMG 轨道吊行业选型参考（额定起重量 41 吨、跨度 31-37m、起升高度 12.2-21m 等，来源 ZPMC/新浪财经/KS Crane/AI Crane 等公开资料），并明确两条最终决定：①正式把额定载荷改成 41 吨；②场桥不做双箱（维持 2026-09-04 已作出的既有决定，`YardCraneGantryDriveModel.cs:187` 注释已记录双箱为岸桥专属能力）。
- 本轮范围限定为"驾驶 Rig 的配置数值 + 场桥自身结构几何 + 学习训练单项目标值"三块，不含堆场箱区/车道/AGV/建筑内容（等待用户提供模型）、不含岸桥（`QuayCraneSimulator` 未立项，单独更大任务）、不含绳索动力学常数的精确调优（只给方向性起点值，需用户 Play 实测调整）。
- 现有可达范围架构是围绕 home 点对称展开的 `[-limit, +limit]` 区间（`YardCraneLocalTrainingModeCoordinator.cs`），因此本轮把 425m/30m 总行程按"home = 行程中点"的既有惯例对半处理；若真实大车停放点并非行程正中，需要用户后续确认再调整。

### 2.2 实际实现

1. **载荷**：`load.maximumContainerGrossMassKg` 40500f → 41000f，直接对应用户"正式改成 41 吨"的决定；`load.minimumContainerGrossMassKg`（2200f，空箱下限）未改动。
2. **大车行程**：`motion.gantryTravelFromHomeMeters` 8f → 212.5f（425m 总行程 ÷ 2，按 home=中点假设对称展开）。
3. **小车跨度**：`motion.trolleyTravelFromHomeMeters` 4.5f → 14f（30m 总跨度扣除两端约 1-1.5m 轨道/结构间隙后的可用行程，对称展开约 ±14m；这是工程假设起点值，不是精确值）。
4. **起升范围**：`geometryAndSafety.minimumSuspendedDropMeters` 2.8f → 3.0f，`maximumSuspendedDropMeters` 8.5f → 24.0f。推导：新结构高度 24m，`spreaderMaximum = trolleyWorldY(24) - minimumSuspendedDropMeters(3.0) = 21m`（与手册"21m 吊具高度"及行业"12.2-21m"区间吻合），`spreaderMinimum = 24 - 24 = 0m`（落地）；3.0m 顶部间隙为占位估计值，非实测硬件间隙。
5. **绳索动力学常数**（方向性估计，非精确计算）：起升行程比例从 5.7m 变为 21m（比值 ≈3.684），自然频率按弹簧/摆系统 `频率 ∝ 1/√行程` 缩放：`loadedSuspensionNaturalFrequencyRadiansPerSecond` 2.35f → 1.22f（÷√3.684≈1.919），`loadedHoistNaturalFrequencyRadiansPerSecond` 9.0f → 4.69f（同比例）；挠度按 `挠度 ∝ 行程` 缩放（×3.684）：`lightLoadedStaticRopeDeflectionMeters` 0.006f → 0.022f，`fullyLoadedStaticRopeDeflectionMeters` 0.018f → 0.066f，`maximumLoadedHoistDeflectionMeters` 0.040f → 0.147f。阻尼比（无量纲）未缩放。`AcceptanceSection`/`RegressionSection`（含既有 30 吨回归基线）、限位安全余量、锁箱/落箱容差、箱体与吊具碰撞体尺寸均未改动。
6. **场桥结构几何**（`YardCraneModelHierarchyBuilder.cs`，纯程序化灰盒，不依赖外部美术模型）：大车腿 X 坐标 ±6f → ±14.5f（对应新 30m 跨度），腿高度 7.6f → 24f（对应新结构高度），顶部横梁长度 12.6f → 30f、Y 坐标同步到 24f；`ApplyDefaultMaxPrototypePose()` 中 `20_TrolleyMotion` 初始高度 8f → 24f，`30_SpreaderPhysics` 初始高度 3.2f → 13.5f（保持约 65% 可达高度比例的初始姿态）。小车/吊具体自身尺寸、八根绳出绳口/导向轮相对小车体的偏移量、箱体初始位置未改动（这些是相对小车/吊具体自身尺寸的小偏移，不直接对应三个宏观尺度数字）。
7. **学习训练单项目标值**（`YardCraneStudentSideShell.cs` 五个 `Start*Drill` 方法 + `StudentSideShell.uxml` 对应 Toggle 标签文本）：参照 `场桥集装箱起重机仿真系统（含远程）用户手册V1.0.docx` §5.2 练习项目的真实设计意图，结合新可达范围换算：
   - 大车移动：`{-6,-3,3,6}` → `{-50,-30,30,50}`，容差 0.20m → 0.5m（手册原值，新范围内可达，直接采用）。
   - 小车移动：`{-3,1.5,3}` → `{-10,5,10}`，容差 0.15m → 0.5m（手册原值 15/35/45m 是绝对坐标不是相对 home 的有符号偏移量，与现有坐标约定不符，改用落在新 ±14m 范围内的推算替代值，非手册原值）。
   - 吊具起升：`{1,-1,-2}` → `{5,-5,-10}`，容差 0.15m → 0.5m（手册原值 5/10/20m 是离地绝对高度，与现有"相对训练开始时刻"的坐标约定不符，改用推算替代值）。
   - 吊具回旋：`{-3,3,-1}` → `{-3,3}`，容差 0.15（原值，误当角度容差复用了米制容差数字）→ 0.5°。移除未见于手册来源的第三档"-1°"选项，改为手册规定的仅"左旋3°/右旋3°"两档；`StudentSideShell.uxml` 同步删除第三个 Toggle。
   - 吊具回零：容差 `holdAfterZero ? 0.10 : 0.15` → `holdAfterZero ? 0.30 : 0.5`。
   - `SelectedToggleIndex`/`BindExclusiveToggleGroup` 均按子元素动态查询 Toggle 数量，未硬编码档位数，回旋选项 3→2 不需要额外改动。

## 7. 修复：任务提醒弹窗缺"开始"按钮 + 任务完成框一闪而过——用户实测证据 + 根因修复

### 7.1 用户实测证据（真实 Play，6节功能上线后第一次测试即暴露两个问题）

用户按6节新流程实测后反馈两个问题：①任务提醒界面只有一个通用关闭按钮，没有"开始"字样，体验不清晰；②任务完成后**没有看到完成框**，直接突然跳转回了学生端首页。贴出的 Play 日志显示：`countdownSeconds=5`（倒计时改动确认生效）、`[YC_LOCAL_LEARNING_GOAL_ACHIEVED] ... score=100`（新增的得分推送确认生效，能拿到真实分数），但紧接着**只隔一帧**就出现 `[YC_UI_HUD_NAV_BACK_REQUESTED]`（来自 `RequestBackNavigation()`），说明 `completionRequested` 轮询在完成框弹出的**下一帧**就发现 `hud.ActivePromptKind == None`，判定弹窗已关闭，触发了返回——但学生根本没有机会点任何按钮。

### 7.2 根因（读代码定位，不是猜测）

读 `YardCraneOperatorHud.cs` 的 `OnLifecycleChanged(previous, next)` 方法，代码自带的注释直接点出了这个坑：
> "Terminal/finalizing truth must not be hidden by a stale task modal. A coordinator may deliberately show the new run's completion prompt **after** this transition, but anything that predates the transition is invalid." → 命中即调用 `ClosePrompt()`。

6节的实现顺序是**先** `hud.ShowCompletionPrompt(...)` **后** `TryFinishLifecycle(YardCraneSceneState.ExitAllowed, ...)`——`TryFinishLifecycle` 内部把场景状态从 `Running/Paused` 经 `Finalizing` 推进到 `ExitAllowed`，每次状态机转换都会触发 `OnLifecycleChanged`；由于完成框是在转换**之前**弹出的，被这段既有逻辑当成"过期的任务弹窗"立即强制关闭——这正是代码注释里明确警告、而6节实现恰好踩中的顺序错误。

### 7.3 修复

- **`YardCraneLocalTrainingModeCoordinator.cs`**：`UpdateGuidedLearning` 达成分支调整顺序为**先** `TryFinishLifecycle(ExitAllowed, ...)` **后** `hud.ShowCompletionPrompt(...)`（转换失败则直接返回、不弹完成框，行为更一致）。
- **任务提醒"开始"按钮**：`YardCraneHudTaskPrompt`（`YardCraneHudPrompts.cs`）新增 `ConfirmText` 字段（默认"×"，向后兼容）；`YardCraneOperatorHud.Prompts.cs` 新增专用的 `taskPromptCloseButton` 字段（原来 `task-prompt-close` 只混在通用的 `promptCloseButtons` 列表里、没有单独引用，无法定制文案），`ShowTaskPrompt` 里按 `data.ConfirmText` 设置按钮文本，点击行为不变（仍是既有的 `ClosePrompt`）；协调器调用处传 `ConfirmText = "开始"`。

private void HandleCompletionDetails()
