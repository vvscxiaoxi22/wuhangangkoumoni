完成后应形成以下稳定结构：

```text
Keyboard Input Source ─┐
                       ├→ YardCrane Input Router
Xbox Input Source ─────┘           │
                                   ▼
                         YardCraneOperatorCommand
                                   │
                                   ▼
                    Standalone Operation Host / v16安全控制器

                                   │
                                   ▼

```

键盘、Xbox或未来PLC都不得直接修改Transform、Rigidbody、绳索长度或箱体父子关系。

## 3. 统一操作命令设计

建议建立不可变的`YardCraneOperatorCommand`或等价模型，至少包括：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sourceId` | string | `KeyboardMouse`、`XboxGamepad`或未来`Gateway` |
| `sequence` | long | 当前输入流严格递增序号 |
| `capturedAt` | monotonic timestamp | 供新鲜度和断连判断使用 |
| `gantryAxis` | float | `[-1,1]`，今天进入语义层但不驱动物理 |
| `trolleyAxis` | float | `[-1,1]` |
| `hoistAxis` | float | `[-1,1]` |
| `hornHeld` | bool | 鸣笛语义，执行逻辑在P0-02补齐 |
| `lockPressed` | edge bool | 单帧锁箱请求，不允许按住重复执行 |
| `unlockPressed` | edge bool | 单帧解锁请求，不允许按住重复执行 |
| `pausePressed` | edge bool | 单机暂停请求 |
| `deviceConnected` | bool | 输入设备健康状态 |
| `handlesCentered` | bool | 死区处理后的三个轴均回中 |

吊具泵、尺寸、回旋等后续动作使用同一个边沿动作扩展机制，不在输入适配器里写业务联锁。

## 5. 输入路由规则

1. `Standalone`模式允许键盘与Xbox共存，但任一时刻只能有一个活动运动输入源。
2. 最后产生超过死区有效轴值的设备成为活动源；轴全部回中后才允许另一设备接管。
3. 锁箱/解锁动作只由当前活动源提交；两个设备同时发动作时拒绝冲突并记录诊断。
4. Xbox死区、响应曲线和轴反向进入配置，不写死在机构控制器。
5. 输入采集在`Update`执行，最新不可变命令在`FixedUpdate`交给v16和物理层，边沿动作只能消费一次。
6. 窗口失焦、活动设备断开、命令达到危险新鲜度阈值或Unity暂停时，三个运动轴立即归零。
7. `Managed`模式不得因为Coordinator/Gateway掉线而自动降级到`Standalone`，防止绕过运行授权。

## 6. Standalone运行上下文

现有v16控制器要求`operationRunId`、租约、输入流和心跳。今天不绕过这些门槛，而是新增本地宿主：

- 启动时创建明确标记为本地的运行ID、租约ID、场景实例ID和输入流ID。
- 固定使用`Local`控制模式，不冒充ROCS远程模式。
- 本地宿主持续发送Owner/Coordinator心跳。
- 输入路由器只向当前本地运行提交命令。
- 退出、暂停、失焦和设备断开时先清零输出，再释放本地运行。
- 平台托管启动仍要求完整启动参数和一次性令牌，不允许使用单机上下文兜底。
