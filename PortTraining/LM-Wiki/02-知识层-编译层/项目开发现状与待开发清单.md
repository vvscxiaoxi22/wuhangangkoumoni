# 港口实训平台项目开发现状与待开发清单

- 基准日期：2026-09-03
- 最近校正：2026-09-03，纳入吊具泵/尺寸、v22旋转逻辑和v23吊具模型/碰撞/传感/挂箱节点物理旋转投影的分级证据
- 文档性质：持续维护的项目总表；用于回答“已经开发什么、还缺什么、下一步先做什么”
- 适用范围：学生端、教师端、NodeService、Gateway、岸桥场景、场桥场景、共享契约及TOS适配
- 状态口径：只使用`已实现`、`部分实现`、`未实现`、`一期不开放`
- 事实依据：当前源代码、Unity Play与Harness证据、项目文档；原型页面和模拟数据不单独算成功能实现

## 1. 状态判定规则

| 状态 | 判定条件 |
| --- | --- |
| `已实现` | 入口、执行、成功/失败回执、持久化、异常恢复均已形成可验证闭环 |
| `部分实现` | 已有真实代码或可运行子能力，但仍缺执行方、跨进程回执、持久化、恢复或正式联调中的一项及以上 |
| `未实现` | 只有规划、接口文档、静态/交互原型，或代码仍是明确占位实现 |
| `一期不开放` | 已由项目范围明确推迟，不作为一期可操作功能交付 |

本表按实际逻辑判断，不以类名、按钮名称、注释、测试名称或页面效果替代验收证据。

## 2. 总体结论

当前已经形成两套Unity工程和一套教师端交互原型：

1. `PortTraining`学生端Unity工程：登录、工作台、任务中心、训练档案、本地模拟设备状态和本地JSON数据能力已具备，整体为`部分实现`。
2. `YardCraneSimulator`场桥Unity工程：八绳MAX灰盒、30吨载荷物理、抓放箱回归、v17单机输入链、大车/鸣笛/夹轮器、低空防碰、关键状态HUD、控制电源/急停/显式复位、大车/小车锚定、吊具泵/尺寸和v23吊具物理旋转投影已形成，整体为`部分实现`。
3. `teacher-prototype`教师端：已有可点击Web原型，但没有真实服务、数据库、发布同步和监控链路，业务功能为`未实现`。

平台级完整生命周期仍未闭环。目前尚不能完成“教师真实发布 → 学生同步 → 启动独立场景EXE → Gateway/PLC控制 → 场景提交结果 → NodeService持久化 → 教师查看结果”的端到端作业。

### 4.2 当前需要特别说明的实现边界

- `S7PlcTransport.Connect()`当前明确抛出`NotSupportedException`，因此真实S7通信是`未实现`。
- `EmbeddedGatewayClient`只能作为模拟输入和接口原型，不能作为最终生产架构。
- “进入驾驶室”和“自由练习”当前只发出C#事件，没有外部EXE执行方，因此不能标记为`已实现`。
- 本地训练记录与画像可以落盘，但尚未接到真实场景结果；现阶段不应生成或展示演示假成绩冒充真实训练数据。

## 7. 岸桥、Gateway、NodeService与TOS待开发重点

### 7.1 岸桥场景

目前只有驾驶HUD交互原型和显示布局结论，正式岸桥Unity工程为`未实现`。需要至少完成：

1. 65吨岸桥真实模型、船舶/码头/岸桥作业车道与AGV场景。
2. 大车、小车、起升、前大梁俯仰、吊具倾转/回旋、导板、中锁和20/40/双20尺。
3. 卸船MVP：船舶箱位抓箱 → 岸桥车道AGV放箱 → 结果提交。
4. 装船、自由练习、排故现象、就地与ROCS视景。
5. 与学生端、Gateway和NodeService使用同一V1.1契约，不能自行复制协议类。

### 7.2 Gateway与PLC

生产Gateway为`未实现`。下一步必须先取得实际PLC型号、Rack/Slot、DB点表、读写白名单和安全超时，再实现：

- 独占S7长连接、批量轮询、断线重连和数据新鲜度。
- PLC地址到统一设备语义的映射。
- `operationRunId`控制租约、模式锁定和序号校验。
- 场景崩溃、心跳超时、急停、PLC掉线时清零输出。
- 学生端只读诊断；场景和学生端均不得直接连接S7。

### 7.3 NodeService与离线协作

NodeService为`未实现`，它是教师发布、学生同步、结果持久化和两学生机协作闭环的关键阻断项。必须实现：

- Authority/Edge角色、SQLite、REST/WebSocket、事件补拉和durable outbox。
- 同机部署、教室局域网部署、只有两台学生机的离线运行。
- 已授权任务缓存、结果补传、版本冲突、重复结果幂等。
- 联合作业协调节点和`coordinationEpoch`；网络分区时暂停，禁止自动选主。

### 7.4 TOS适配

TOS适配为`未实现`。一期至少冻结契约和沙箱边界；正式联调可在主闭环稳定后进行。TOS只能生成业务任务，不能访问Unity、PLC或直接发送运动控制。

## 8. 平台操作闭环审计

| 生命周期步骤 | 当前状态 | 结论 |
| --- | --- | --- |
| 教师创建并发布工单 | `未实现` | 只有教师端前端演示数据 |
| 学生同步/离线缓存工单 | `部分实现` | 只能读取本机随包JSON，不是同步缓存 |

## 9. 后续开发优先级

### 9.1 2026-09-01优先级决策

`YardCraneSimulator`是当前最高优先级和核心交付物。先把它做成不依赖学生端、教师端、NodeService和PLC也能独立运行的场桥全流程模拟器；平台接入与真实PLC接入在该闭环稳定后实施。

必须同时满足两种输入路径：

```text
键盘 / Xbox手柄 ─┐
                  ├→ 统一操作语义 → 作业授权与安全联锁 → 机构运动命令 → 场桥物理与反馈
未来PLC/Gateway ─┘
```

运动控制不得直接读取键盘键值、Xbox按键或PLC地址。输入适配器只负责产生统一操作语义；作业状态机负责判断动作是否允许；机构控制器只执行通过联锁后的运动命令。未来接PLC时只新增Gateway输入适配器，不重写场桥运动和业务流程。

### P0：场桥单机全流程作业模拟

#### P0.1 单机运行与输入解耦

当前状态：`部分实现`（校正至2026-09-02）。统一命令、Input System键盘/Xbox适配、单活动源路由、Standalone宿主、Managed禁止静默降级、Bootstrap加载、Windows构建及Player启动已经形成；路由已补充安全离散意图不得被另一设备抢占。尚缺人工连续键盘、实体Xbox、拔出/失焦、最新显式复位Play验收，以及`.inputactions`资产和持久化重映射，因此不得标记`已实现`。详见[场桥YC-P0-01开发计划](场桥YC-P0-01开发计划-单机输入与运动解耦.md)。

1. 建立场桥统一操作命令模型，至少覆盖大车、小车、起升、锁销、解锁、喇叭、急停/复位及后续吊具功能。
2. 接入Unity Input System，完成键盘与Xbox手柄两套可配置映射、死区、曲线、反向、灵敏度和断开检测。
3. 建立输入源接口和运行时选择：`KeyboardMouse`、`XboxGamepad`、未来`Gateway/PLC`使用完全相同的语义输出。
4. 将输入、业务动作、安全联锁、机构运动和物理反馈分层，禁止输入适配器直接修改Transform、Rigidbody或绳长。
5. 单机启动不要求RunTicket；使用明确的`Standalone`本地运行上下文。平台托管启动继续使用`Managed`上下文，两者不得混淆授权状态。

#### P0.2 补齐场桥核心机构

当前状态：`部分实现`（校正至2026-09-03）。大车物理驱动、夹轮器互锁、鸣笛、方向性低空防碰和关键状态HUD已加入；控制电源/急停/显式复位以及大车/小车锚定已有分级证据。吊具泵/尺寸与v22旋转逻辑已形成，v23进一步完成吊具相对上架的模型、碰撞、传感与挂箱节点旋转投影，并通过Harness、Unity程序集编译和Play初始化绑定。实际±3°/回零烟测、30吨组合回归、Windows Player和实体Xbox仍未完成；“开动前鸣笛”规则归属未定。详见[场桥YC-P0-02开发计划](场桥YC-P0-02开发计划-大车鸣笛与夹轮器.md)及`PortTraining/Docs/讨论记录/2026-09-03.md`第2条。

1. 在现有八绳MAX、小车、起升和载荷物理上补齐大车运动、加减速、制动和惯性。
2. 完成大车两端、小车两端、起升上下限、减速区和越限阻断。
3. 完成四角着箱、锁销/解锁、错锁/未全锁、悬空解锁阻断和状态反馈。
4. 逐步补齐吊具泵、夹轮器、回旋、20/40尺状态；未完成的机构必须明确禁用，不能返回假成功。
5. 保持v12动力学、v15 Profile和v16 SafeHold回归门槛，不因新增业务流程放宽现有验收标准。

#### P0.3 建立本地任务与堆场业务环境

1. 在场桥程序内提供轻量单机任务选择：自由练习、本地预置任务、重新开始和退出。
2. 建立堆场箱区、`Block/Bay/Row/Tier`箱位、海侧AGV/内集卡作业位、陆侧外集卡作业位和车辆到位状态。
3. 箱体、车辆和目标箱位必须由任务数据驱动，不能把流程写死在某一组场景坐标。
4. 本地任务模型与未来平台工单字段保持映射关系，但单机运行不依赖外部服务。

#### P0.4 场桥四类全流程任务

按以下顺序形成可玩的闭环：

1. **卸船转堆MVP**：海侧AGV/内集卡到位 → 对位 → 着箱锁定 → 带载起升 → 大车/小车转运 → 目标箱位落箱 → 解锁 → 车辆/任务状态完成。
2. **装船出堆**：堆场目标箱位抓箱 → 海侧车辆作业位放箱 → 交接完成。
3. **陆侧收箱**：外集卡到位 → 抓箱 → 指定堆场箱位落箱 → 车辆离场。
4. **陆侧提箱**：指定堆场箱位抓箱 → 外集卡放箱 → 交接完成。

每类任务都必须包含任务开始、目标提示、车辆到位、抓放箱条件、错误操作拒绝、完成/失败反馈、本地结果记录和一键重新开始。

#### P0.5 单机体验与验收

1. 完成驾驶视角、必要HUD、任务步骤提示、吊具/锁销状态、暂停、设置和退出。
2. 支持Xbox和键盘完成同一任务，任务中允许按规则切换这两种桌面输入；未来`Local/ROCS`控制模式仍只能在任务开始前确定。
3. 建立自动回归与人工操作用例：空载、30吨、错误锁箱、低净空、悬空解锁、越限、急停、手柄未回中和输入设备断开。
4. 本地保存任务用时、是否完成、关键安全事件和最终箱位，为后续学生档案接入提供真实结果源。

P0完成标准：不启动学生端、教师端和PLC服务，直接运行`YardCraneSimulator.exe`，操作者使用Xbox手柄或键盘可以独立完成上述四类任务；正常路径、拒绝路径和急停恢复均有明确反馈，退出重进后本地结果可查询。运动代码不依赖任何具体输入设备或PLC地址。
